# M4: the in-browser engine wired into the app (not yet tested)

What M4 connected, where it lives, what is still open, and the commands for the test pass (M6). The spec for all of
it is ARCHITECTURE.md sections 1-7.

## What was wired

* **Two transports behind one facade.** `ApiService` now delegates every call to the `TRANSPORT` token
  (`core/transport/token.ts`). `ServerTransport` is the old HTTP + SSE body, moved unchanged. `BrowserTransport` runs
  everything in the tab. The build picks one: `production` (the static site) swaps `src/environments/environment.ts`
  for `environment.browser.ts` (browser); `development` (`ng serve` + proxy), the new `self-hosted` configuration and
  the unit tests keep `server`. The Dockerfile, the root `npm run build` and `scripts/run.mjs start` now build
  `self-hosted`, so the self-hosted edition keeps talking to the Python API.
* **Transport additions** (both transports implement them): `kind`, `exportBlob(id, format, extra) -> {blob,
  filename}` (the job page's downloads), `logsStream(after)` (the Logs page's live stream), `deleteSession({
  deleteModels })`. `exportUrl` / `exportText` / `logsStreamUrl` stay (Copy still uses `exportText`).
* **Engine worker** (`engine/worker/`): `pipeline.ts` is the ARCHITECTURE section 3 pipeline as one function with
  injected I/O: `decodeMedia` (+ clean-up) streaming into `StreamingVad(WHISPER_VAD)`, `planWindows(WHISPER_PLAN)`,
  the faster-whisper seek loop over the joined speech timeline (restart at `seek + consumedSeconds`, last-word rule,
  no-speech window skip, hallucination-silence guard with word timing, language detection on up to 4 x 30 s,
  previous-text prompt with the temperature reset), `restoreSpeechTimestamps`, `SegmentFilter` + `withOriginalText`.
  `worker-core.ts` holds the real dependencies (Silero with the canary and the energy fallback, `WhisperEngine`,
  `ModelManager.ensure`) and the message handler; `transcribe.worker.ts` is the entry; `protocol.ts` the messages
  (section 4 plus `log`, `recycle`, `result`). `WorkerClient` runs one job at a time, cooperative cancel, hard cancel
  (terminate, fresh worker on the next run) after 2 s, and the WebGPU recycle every 40 windows (the worker sends its
  state, the client restarts it and continues the same run).
* **Job runner** (`engine/jobs/`): `JobRunner` is jobs.py's queue on `SessionStore`: one job at a time, phases,
  progress and `eta_seconds` (post/job-rules), cancel (queued at once, running through the worker), re-run with merged
  options (explicit `null` language honoured), delete (409 while running, like the server), edits (`applyEdits`),
  rename (`cleanTitle`), "apply style only" (`IndicXlitHinglish.restyle`, version check), stats (`computeStats`),
  wake lock while working, the server's error statuses and wording. Hinglish runs on the page through the lazy
  IndicXlit worker (`hinglish-converter.ts`). `options.ts` ports schemas.py and adds the device gate; `reference-data.ts`
  holds the server's model list and languages.
* **BrowserTransport**: health synthesised (`runs_in: 'browser'`, `public: false`, logs on, no limits), models from
  the server's list + `planFor` (sizes of the device's download, `default`, `reason` for hidden models, Qwen listed
  with the reason "Qwen3-ASR in the browser is being added; use Whisper for now."), languages, session / delete my
  data (optionally the model cache) from `SessionStore`, jobs from the runner, watch = the SSE shapes in process,
  exports rendered by `engine/export` (byte-identical), PDF through the print view (`print-view.ts`, hidden frame +
  `window.print()`), media as an object URL of the stored file, stats `{0, counting: false}`, logs from the in-page
  `LogRing` (`log.service.ts`). The engine runtime (`browser-engine.ts`) is a lazy chunk.
* **UI**: model pickers (upload + re-transcribe) list every model; those the device cannot run are disabled with the
  plan's reason, Qwen disabled with the reason above; the device plan picks the starting model and its notes are shown;
  "first time only: downloads N MB" from the catalog sizes; word-timing note; a time estimate and the weak-device /
  long-file warnings (`EngineDevice.advice`); "Preparing" instead of "Uploading"; the model-download line during
  `loading_model`; a leave-page guard while a browser job runs; the browser data note and "also delete the downloaded
  models" on Delete my data now; session banners also in browser mode (the store expires idle sessions); Logs page
  on the tab's own log.

## Known gaps

* Nothing was run: no `ng test`, no build, no browser. `tsc` (app + spec) and `ngc --noEmit` (templates) are clean.
* Low-memory devices (`deviceMemory <= 4`) still keep the whole PCM (`collect: true`); the "current window only"
  mode of ARCHITECTURE section 3 is not implemented.
* No preview for files the browser cannot play (.mkv, .avi, .mov outside Safari ...): `media_url` is null, the player
  is hidden (UI-078). The server makes an mp3 preview.
* The model is loaded after decoding, not in parallel (the server overlaps them).
* Copy for the browser edition (privacy, terms, FAQ, how-it-works, `browser` site mode of UI-123) is not done: the
  browser edition uses the local install's wording plus the few browser lines above. Prerendered pages still say the
  public-site wording until the synthesised health arrives (UI-020).
* The counter is `{transcribed: 0, counting: false}` (the Worker + D1 counter is a later milestone), so the header pill
  shows the local-copy variant.
* Decode warnings and partial text are logged, not shown on the page.
* Qwen3-ASR is listed and disabled (M5). The pipeline refuses it with the same text.
* Worker bundling relies on Angular's `new Worker(new URL(...), import.meta.url)` detection, as the existing audio and
  IndicXlit workers do; the ORT runtime for Silero comes from the pinned jsDelivr URL (same as Whisper's).

## Test commands (M6)

From `frontend/`:

```
npx tsc --noEmit -p tsconfig.app.json
npx tsc --noEmit -p tsconfig.spec.json
npx ngc -p tsconfig.app.json --noEmit
npx ng test --watch=false --include "**/core/transport/*.spec.ts"
npx ng test --watch=false --include "**/engine/{jobs,worker}/*.spec.ts"
npx ng test --watch=false                       # everything: the old specs must pass unchanged on ServerTransport
npx ng build --configuration production         # static site (browser transport)
npx ng build --configuration self-hosted        # self-hosted edition (server transport)
```

Then in a browser (`ng serve --configuration production`, or the built `dist/frontend/browser` behind a static
server): a short WAV / MP3 with tiny on WASM and base on WebGPU, cancel during the encoder (hard cancel), a > 40-window
file on WebGPU (recycle), Hindi with Hinglish on, reload during and after a job, every export, PDF print, Delete my data
now with and without the models, the Logs page.
