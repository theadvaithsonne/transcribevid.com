### End-to-end run

Static server emulating Cloudflare Pages over the post-built `dist/frontend/browser` (flat `x.html`, the `_redirects`
rewrites `/jobs/:id` and `/logs` -> `/index.csr`, `404.html`); headless Chrome; huggingface.co and jsDelivr from the
replay cache. Checks:

* `/` makes no request to huggingface.co / jsDelivr until a job starts (23 same-origin requests);
* tiny is offered; `passage-c-44k-stereo.wav` (44.1 kHz stereo, so resample + downmix) -> job page -> **done in 11.6 s**
  (model fetch from the replay cache included);
* transcript "Please remember to submit your report by Friday April 12th, and send a copy." -> **WER 0.0 %** against
  the manifest's `expectedText` prefix (14 words) after normalisation; 92 % model confidence;
* Export SRT (valid cue syntax) and Plain text (.txt) download;
* reload: same URL, same job and text;
* Delete my data now: both questions asked, the job page then says "Transcript not found", `transformers-cache` emptied;
* `/`, `/faq`, `/privacy` at **390 px and 1440 px**: no horizontal scroll (document, body and `main`; no element past the
  viewport); the rail element is in the DOM on `/` and `/faq` and absent on `/privacy` (its visibility per width was
  not measured; screenshots in `scratchpad/m6/e2e-out/`);
* **no request to any Google ad host** in the whole run and no `adsbygoogle` script in any page (ads inert: no slot ids).

The only console errors are the counter's (`https://transcribevid.com/api/stats` and `/count` blocked by CORS from
`localhost`): expected locally, same-origin in production, and the pill hides on error.

## Fixes

Code (behaviour now matches the server where the module docs say so):

* `engine/vad/windows.ts`: `pyRound` tested ties after a rounded division, so `round(2.675, 2)` gave 2.68 (Python:
  2.67); it now delegates to the exact `post/py.ts` implementation.
* `engine/post/py.ts` (new `pySum`), used in `post/segment.ts` (confidence), `post/stats.ts` (speech seconds, average
  confidence), `post/guards.ts` (anomaly score): Python 3.12's `sum()` of floats is Neumaier-compensated; the plain loop
  differed in the last bit and flipped `round(5.769 / 6, 3)` (golden: 0.962, port: 0.961).
* `engine/hinglish/indicxlit.ts` (`attentionModes`, `remainderRows`), `engine/hinglish/kernels.ts` (JS `attendHead`),
  `public/models/indicxlit/kernels/indicxlit-kernels.as.ts` (+ regenerated `indicxlit-kernels.wasm.ts` and
  `provenance.json` via `backend/tools/export_indicxlit_kernels`): the port was **not bit-exact for words longer than
  about 140 symbols** (the spike's "positions" diagnosis was wrong: the shipped table is identical to CT2's). oneDNN's
  nocopy sgemm driver blocks the query rows (BN 96 for q.k, 48 for p.v, the last 1.5-2 blocks halved) and p.v's keys
  (BK 256, halved the same way, blocks summed into C); the 1-3-row remainder kernels apply per block. Now equal to
  CTranslate2's scores bit for bit at 150, 160, 240, 253-257 and 300 symbols, and `अ` x 257 gives the server's 16 a's.
  `export_indicxlit_kernels --check`: up to date.
* `engine/audio/decode.ts`: (1) the MP3 encoder padding at the end is now dropped like ffmpeg's demuxer
  (`first_discard_sample`..`last_discard_sample`); the extra 431 samples changed dynaudnorm's last frames
  (`tone-1k.mp3` 15.3 dB -> 89.7 dB vs ffmpeg, duration 3.00 s exact). (2) The block loop yields a task once before
  the first block and then every 16 ms (a timer turn in a window, a MessageChannel turn in a worker): in-memory reads
  resolve as microtasks, so a main-thread decode never let an abort timer or the UI run (A/B on a 5-minute WAV: without
  the yield "decoded" after 165 ms despite an abort at 5 ms; with it CANCELLED). Costs ~20 % on main-thread decodes
  only (the timer clamp); the app decodes in workers.
* `core/log.service.ts` + new `core/transport/kind.ts` (`TRANSPORT_KIND` moved there, re-exported by `token.ts`, to
  avoid an import cycle): **the browser edition POSTed client log lines (which can name the visitor's file) to
  `/api/logs/client`** before the synthesised health switched sending off. It never sends now; the in-page log keeps
  everything. Found by the end-to-end run (a 404 on the static host; in production that path is the counter Worker's
  route).
* `features/legal/privacy.{html,ts}` + `legal.scss`: section "12. Open-source components" in the browser edition,
  rendered from `THIRD_PARTY_NOTICES` (`engine/models/licences.ts`: ffmpeg.wasm GPL-2.0-or-later with source link and
  offer, Qwen3-ASR Apache-2.0), "Changes" is now 13; long URLs wrap on phones.

Test data:

* `engine/audio/golden-fixtures.ts` `FILTERS_GOLDEN`: regenerated with `aformat=sample_fmts=dblp` before the filters
  (`scratchpad/m3-audio/make-golden.mjs`). The old golden ran highpass / lowpass on s16 with rounding after each stage,
  which production never does (dynaudnorm forces double); the DSP now equals it exactly (max difference 0).

Specs changed (the spec was wrong, not the code):

* `engine/jobs/job-runner.spec.ts`: the cancel test expected `'kept'`, but the default `output_script` is `hinglish`
  and the language `en`, so the server converts each segment as it is recognised (engine.py:513): `'kept (roman)'`.
* `engine/vad/windows.spec.ts`, `segmenter.spec.ts`, `streaming.spec.ts`, `engine/audio/dsp.spec.ts`: explicit
  timeouts (60-120 s) on six heavy property / long-input tests. The 1500-case planner property takes ~16 s alone
  (`planWindows` itself 0.1 s for 1500 calls; the oracle and ~10^5 `expect`s are the cost), and two others timed out at
  the 5 s default only under the full parallel suite.

Specs added: `legal.spec.ts` (open-source section in the browser edition, none in the server editions),
`log.service.spec.ts` (browser edition never sends).

Harness (scratch, not the repo): `m3-audio/run-conformance.mjs` runs its cancel checks on a generated 5-minute WAV
(the 50 s fixture decodes in 28 ms, so an abort at 5 ms raced the whole decode).

## Not verified here / still open

* **Safari, Firefox, real phones and tablets**: nothing measured (no such browser or device on this machine). The
  low-memory path (`lowMemory`), the WASM-only plans and the in-flow ad layouts below 1100 px are only exercised by unit
  specs and the 390 px Chrome check.
* **Real AdSense**: no slot ids exist, so only "inert" was verified (no loader request, house note). Loader, push,
  consent message and ad-blocker behaviour wait for the owner's ids (M5.md, owner steps).
* **Real Cloudflare deploy**: Pages, `_headers` delivery, the counter Worker + D1 and `wrangler pages dev` were not run;
  the end-to-end used a Node server that emulates the post-build's rewrites.
* **Qwen3-ASR and the large Whisper models** (incl. the large-v3 / distil-large-v3 word-timing aligner): unit specs
  only, by instruction; no end-to-end run. ffmpeg.wasm conversion (AVI / WMA / AMR ...), the WAV preview player, the
  WebGPU 40-window recycle and Hindi + Hinglish in the app were not driven end to end either (their specs pass).
* Build warnings (not errors): the SSR / prerender bundle pulls `sharp` through Transformers.js's Node build (three
  "not ESM" warnings); harmless for the static output.
