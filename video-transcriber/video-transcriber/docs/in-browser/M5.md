# M5: the site (ads, consent and privacy text, Cloudflare Pages, counter Worker) (not yet tested)

What M5 built for the static website, the owner's dashboard steps, the deploy steps, what is still open, and the
commands for the test pass (M6). Specs: `spike/adsense.md` sections 6-11, 14, 16; `spike/hosting.md` sections 0, 1.3,
7, 8; `PARITY.md` section 3.

## What was done

**Ads (inert until every slot id exists).** `core/ads.service.ts` decides where ads may appear. The route data `ads`
is `true` on home, how it works, FAQ and the six tool pages, and `'job-done'` on `/jobs/:id`, so a transcript is an ad
page only once it is finished. Nothing else is an ad page: privacy, terms, logs, 404, and a transcript that is queued,
running, failed or cancelled. Ads appear only in the edition that has them (`environment.ads`: true in
`environment.browser.ts`, false for the local and self-hosted builds), and only when `adsConfigured()` is true. When
both hold, the service:

* appends Google's loader once, in the browser only, never while prerendering, the first time a slot is about to
  request an ad;
* requests no new ad while anything is queued or running in this tab. The space stays reserved.

`shared/ad-slot.ts` is one manual unit in a reserved box with a fixed minimum height: 600 px for the rail, 250 px for
in-flow units, plus a 22 px label line. The label "Advertisement" shows only while the box holds an ad. The house note
"Ads keep TranscribeVid free. Everything works without them." shows when the box is inert, when the unit is unfilled,
when the push throws and when the loader is blocked.

* **Size.** The size is decided once per instance by `adSizeFor`: the rail is 160x600 from 1100 px and 300x600 from
  1680 px; in-flow units are 300x250 from 332 px up to 1100 px (up to 1000 px on home and transcript, which fit the
  window from there). A resize never requests a new ad.
* **When it pushes.** The rail pushes after `requestIdleCallback`. In-flow units push when an `IntersectionObserver`
  (root `main`, 300 px look-ahead) says the box is near. In both cases the box must have a width, and each instance
  pushes exactly once.
* **The `ins`.** It carries `data-tag-for-age-treatment="0"`. A `MutationObserver` reads `data-ad-status`. On destroy
  the slot removes its own `ins` only.
* **Hidden cases.** `prefers-reduced-data` and print hide the unit, and a hidden box gets no push.

`shared/ad-rail.ts` is the rail; `app.scss` "ad rail" places it.

* **Wide windows (1100 px and up).** On ad pages the shell grid becomes `minmax(0,1fr) 20vw`. The header spans both
  columns; the page (which still scrolls inside `main`) and the footer sit on the left; the rail runs from below the
  header to the bottom. The unit stays in view without `position: sticky`, because only `main` scrolls. A window too
  short for 600 px makes the rail scroll on its own.
* **Narrower windows.** Below 1100 px there is no rail. The FAQ (after the fourth question), how it works (after the 3
  steps) and the tool pages (after the "why" section) have one in-flow unit in their template. Home and the finished
  transcript get theirs from the shell, after the page: route data `adSlot: 'end'`, 48 px clear of the page's buttons.

A new page view gets a new `ins`. Routed pages get new instances. The shell's end unit is keyed on the path. The rail
is keyed on `viewKey`, which changes on a route change at most once per 30 s after the last request.

The print rules are in `styles.scss`, `app.scss` and both components. The global `--gutter` is now 16 px on phones, so
a 300 px unit fits from 332 px.

**Consent.** Google's own consent tool (Privacy & messaging) needs no code beyond the loader. The footer has a **Privacy
and cookie settings** button. That is Google's required link text; the brief said "Privacy settings". It shows only on
ad pages and only once ads are configured, so it is hidden while ads are inert, and on privacy, terms and logs.

* **On click.** It calls `googlefc.showRevocationMessage()`. If the consent tool is not there yet, it queues the call
  on `googlefc.callbackQueue` (`CONSENT_DATA_READY`) and loads the loader. If the script is blocked, a toast says so.
* **Ad-free pages.** The `adFreeDocument` guard on privacy, terms and logs opens them with a full page load once Google's
  script is in the tab, so those documents never carry ad code (Google requires a script-free privacy policy URL). It
  does not do this while a transcription runs.

**Text (true for the browser edition, unchanged for the server transport).** `SiteService` now knows the build:
`TRANSPORT_KIND 'browser'` makes the browser edition's own health the assumed answer, so `inBrowser()` is true from the
first render, including the prerendered HTML that crawlers and the AdSense review read.

The pages that branch on it:

* privacy (12 sections): on-device processing, IndexedDB, Hugging Face and jsDelivr downloads, Cloudflare hosting, the
  counter, AdSense with the Google cookie, partner and opt-out text (adssettings.google.com, aboutads.info, the
  partner-sites link), consent, not directed to children under 13 / 16, and "Delete my data now" cannot delete Google's
  cookies;
* terms: device limits, ads, third-party downloads, children;
* FAQ, how it works, the six tool pages (a typed `browser` variant per paragraph through `editionText`), the tool-drop
  hint, and the free-chips line.

The promise used on every page: "Your file never leaves your device. Ads appear only on information pages and beside
finished transcripts, and are served by Google, which uses cookies." The server-edition wording is unchanged, so the
specs that pin it keep passing. `LEGAL_UPDATED` is 26 October 2026.

**Cloudflare Pages.** `scripts/pages-postbuild.mjs` (run by `npm run build:pages` in `frontend/`):

* flattens every `dir/index.html` to `dir.html`;
* copies `index.csr.html` to `404.html`;
* writes `_headers`: security headers, immutable cache for hashed `main-/chunk-/polyfills-/worker-/styles-` files and
  `/media/*`, a day for `/models/*` and icons, an hour for robots, sitemap and ads.txt, `ads.txt` as
  `text/plain; charset=utf-8`, noindex for `/jobs/*`, `/logs`, `/index.csr`, `/404` and the `*.pages.dev` host;
* writes `_redirects`: `/logs` and `/jobs/:id` to `/index.csr 200`, `/about` to `/how-it-works 301`;
* checks the build and exits 1 on a problem: files over 25 MiB, 20,000 files or more, more than 100 header rules, a
  duplicated pattern, lines over 2,000 characters, an unflattened page, a sitemap URL without its page, a missing
  ads.txt.

There is deliberately **no COOP/COEP** anywhere (the no-isolation decision in `PROGRESS.md`; ads cannot load in an
isolated document). The `/jobs/*` block of `hosting.md` section 7 therefore lost its isolation headers.

**Counter.** `workers/counter/` holds `wrangler.toml`, `schema.sql`, `src/index.ts` and `tsconfig.json`.

* `GET /stats` answers `{transcribed, counting: true}` with a 5-minute browser cache.
* `POST /count` takes no body. It returns 403 unless the Origin is in `ALLOWED_ORIGINS` (`https://transcribevid.com`),
  and 429 past 10 requests per IP per minute. The limit uses the Workers Rate Limiting binding when present, else a
  per-isolate in-memory limit. The increment is one atomic `UPDATE counter SET n = n + 1 WHERE id = 1 RETURNING n`.
* Both paths also answer under `/api/`. Any D1 error answers 503. CORS covers the site's origin, and nothing is stored
  but the total.

`core/stats.service.ts` reads the counter's URL from `COUNTER_URL`, which is `environment.counterUrl` (`''` in the
server editions, so they keep `/api/stats`; `https://transcribevid.com/api` in the browser build). It reads
`<url>/stats` and POSTs `<url>/count` once for each transcript that this tab saw queued or running and that is now done.
It does not count a list loaded after a reload, or another tab's work. The tooltip says "as reported by visitors'
browsers"; the number is never called verified. Any error hides the pill.

**Responsive (checked by reading, not in a browser).**

* At 320-1099 px there is no rail, the gutters are 16 px, and an in-flow unit appears only from 332 px. Its box is
  `max-width: 100%; overflow: hidden`, so it never scrolls sideways.
* At 1100-2560 px the page column is `minmax(0,1fr)` (and `main` keeps `min-width: 0`). The rail is 20vw with
  `overflow-x: hidden`. The unit fits its usable width at every width: 196 px at 1100, 312 px at 1680.
* The header spans both columns; the footer wraps.
* Watch item: the home page's two-column layout (`minmax(0,1fr) minmax(420px,500px)`) leaves the drop zone column only
  about 277 px at 1100 px with the rail. Nothing overflows, but look at it at 1100-1200 px in M6.

## Owner: Cloudflare (free plan)

1. **Domain**: add `transcribevid.com` as a zone (move the nameservers to Cloudflare). SSL/TLS: turn on **Always Use
   HTTPS**. HSTS comes from `_headers`; do not also set it in the dashboard.
2. **Pages project**: Workers & Pages > Create > Pages.
   * Either connect the Git repo with root `video-transcriber/video-transcriber/frontend`, build command
     `npm ci && npm run build:pages`, and output `dist/frontend/browser`. Set the environment variable `NODE_VERSION`
     to `22` (Angular 21 needs Node 20.19 or later);
   * or deploy from a machine: in `frontend/`, run `npm run build:pages`, then
     `npx wrangler pages deploy dist/frontend/browser --project-name transcribevid`.
   * Custom domains: add `transcribevid.com` (apex) only.
3. **www -> apex** (`_redirects` cannot do host redirects):
   * add DNS record `A www 192.0.2.1`, proxied;
   * add a Bulk Redirect list entry from `www.transcribevid.com` to `https://transcribevid.com`, 301;
   * tick preserve query string, subpath matching, preserve path suffix and include subdomains;
   * enable it with a Bulk Redirect rule.

   Do not attach `www` to the Pages project.
4. **Counter (D1 + Worker)**: in `workers/counter/`:
   * run `npx wrangler login`;
   * run `npx wrangler d1 create tv-counter` and paste the printed `database_id` into `wrangler.toml`;
   * run `npx wrangler d1 execute tv-counter --remote --file schema.sql`;
   * run `npx wrangler deploy`.

   Notes:
   * The `routes` line puts the Worker at `transcribevid.com/api/*`, the same origin as the pages, so it needs the zone
     from step 1. Until then, comment it out and set `counterUrl` in `environment.browser.ts` to
     `https://tv-counter.<account>.workers.dev`.
   * If wrangler rejects the `[[ratelimits]]` block, delete it: the code falls back to an in-memory per-IP limit.
   * On Windows, local `wrangler dev` with D1 needs a short project path (MAX_PATH, `hosting.md` 3.5).
5. **Smoke test**: `hosting.md` section 9, except that `/jobs/abc123` must now answer 200 with **no** COOP/COEP headers.
   Then check the counter:
   * `curl https://transcribevid.com/api/stats` answers `{"transcribed":0,"counting":true}`;
   * a POST without an Origin header answers 403;
   * `curl -X POST -H "Origin: https://transcribevid.com" https://transcribevid.com/api/count` answers
     `{"transcribed":1,...}`.

   Free ceilings: 100,000 Worker requests a day (reads and writes together) and 100,000 D1 row writes a day; past them
   the pill hides.

## Known gaps

* Nothing was run: no `ng test`, no build, no browser, no wrangler. `tsc` (app and spec) and `ngc --noEmit` are clean for
  every M5 file. `node --check` passes for the post-build script, and `tsc --strict` passes for the Worker. The only
  remaining type errors are in M5b's files under `engine/**`, which are mid-edit.
* Recording on the home page does not pause ad requests (`adsense.md` 12.2 rule 4). The recording state lives in
  `upload.ts`, which is M5b's file. Ads already pause while any job is queued or running.
* Google's ad script, once loaded on an ad page, stays in the tab when the visitor starts a transcription with a client
  route change, though no new ad is requested. The privacy text claims no more than that.
* For US-state visitors, re-opening the "Do Not Sell or Share" choice relies on Google's own link (the US message can
  place it). Only `showRevocationMessage` (the EEA/UK/CH message) is wired.
* No `/contact` page (the contact e-mail placeholder is kept); `adsense.md` 16 lists one as optional.
* The `Content-Type` rule for `/ads.txt` duplicates what Pages already sends. Check in the smoke test that the header
  appears once; delete the line if it is doubled.
* The words "upload" and "Upload the video" remain as generic verbs on the tool pages; only the sentences about where
  data goes have edition variants.
